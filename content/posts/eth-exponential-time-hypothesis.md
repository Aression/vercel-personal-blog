2026 年 10 月 26 日，OpenAI 发了一篇公告，说自己内部的一个模型证伪了指数时间假设（Exponential Time Hypothesis，ETH）。当天 Hacker News 上那个帖子 778 点，282 条评论。国内几个群里也转了，有一半人以为说的是以太坊。

不是以太坊。ETH 讨论的是 3-SAT 最快能有多快，跟区块链无关。它比 P 与 NP 冷门得多，但比 P 与 NP 更常被引用：过去二十多年里，几百篇算法论文用「假设 ETH 成立」来证明自己那个问题不可能更快。

现在地基被抽走了一块。这篇想把事故讲清楚：ETH 到底断言了什么，那个算法做了什么，哪些结论真的倒了、哪些只是形式上倒了。

## 公告说了什么

OpenAI 同一天宣布了三项结果，分别是数学、计算机科学、物理。CS 这一项是：对每个固定宽度 k ≥ 2，都存在一个确定性算法，能在亚指数时间内精确统计 k-CNF 的满足解个数。

论文标题就是 THE EXPONENTIAL TIME HYPOTHESIS IS FALSE，PDF 元数据里的标题更直接，写着 ETH is False。日期 10 月 17 日，10 月 25 日修订到第三版。模型 10 月 16 日给出证明，10 月 17 日 Lean 形式化通过，10 月 26 日连同 Lean 文件一起公开在 `github.com/openai/math`。

公告里有个安排值得单独说。OpenAI 把这几份手稿称为「原始研究数据」，把「变成科学理解」这一步交给外部专家，CS 这一项的组织者是 Russell Impagliazzo、Ramamohan Paturi 和 Ryan Williams。前两位是 1999 年提出 ETH 的人，第三位是「用更快的 SAT 算法推出电路下界」这条技术路线的开创者。

让原提出者和主要对手方一起组织验证，这个姿态是到位的。但话也得说清楚：这是 OpenAI 的声明，加上 Lean 形式化和公开论文，不等于通过了同行评审。Lean 通过检查意味着定理在形式化语句下成立，不意味着形式化语句就是大家想说的那句话。这两件事之间隔着一大段距离，做过形式化的人都清楚。

还有一条反对意见值得记下来。数学与 AI 顾问组（AGMAI）在 10 月 25 日发过声明，反对把 AI 结果先交给少数内部专家看，理由是这会制造信息不对称。

## 3-SAT 到底是个什么问题

所有故事都从这张纸开始。

给一堆布尔变量 `x1, x2, ..., xn`，每个只能取 0 或 1。再给一堆子句，每个子句是若干个文字（变量或它的否定）的「或」，整个公式是所有子句的「与」。这种形式叫 CNF（合取范式）。每个子句最多 3 个文字，就叫 3-CNF。

举个具体例子，4 个变量、4 个子句：

```text
F = (x1 ∨ ¬x2 ∨ x3) ∧ (¬x1 ∨ x2) ∧ (¬x3 ∨ ¬x4 ∨ x1) ∧ (x4 ∨ ¬x2)
```

SAT 问的是：有没有一组赋值让所有子句同时为真。上面这个例子有，`x1=1, x2=1, x3=1, x4=1`，逐条验一遍就能确认。

另一个问题叫「#SAT」：有多少组赋值满足。这个更强，数出来是 0 就直接回答了 SAT。

最笨的办法是把 `2^n` 组赋值全试一遍。n=20 是一百万次，还行；n=50 是 1 后面 15 个零，GPU 也扛不住；n=1000 就别想了，宇宙里的原子数都不够。

过去三十年，这个指数底数一直被往下压：

```text
算法                                  3-SAT 时间复杂度
穷举                                   2^n
Schöning 随机局部搜索（1999）           (4/3)^n ≈ 1.333^n
PPSZ 及后续分析（2005 起）              ≈ 1.308^n
Liu 确定性分支 + 去随机化局部搜索（2018）  1.32793^n
Jiang–Cai 随机算法（2026，preprint）     1.307031578^n
```

底数从 2 掉到 1.33，然后越来越慢，1.333 到 1.308 到 1.3070。ETH 的心理背景就在这张表里。

## 从 P 与 NP 到指数底数

传统复杂性理论问的是多项式时间够不够，这就是 P 与 NP。它的世界观很粗：`n^100` 和 `n^2` 都算快，`2^n` 算慢。

对真要跑代码的人来说，这个粒度不够用。`1.3^n` 和 `2^n` 在多项式意义上都叫指数，实际差的是天文数字。

2000 年代之后出现了另一条路，叫精确指数算法和细粒度复杂性。它换了个问法：这个问题的最优指数底数是多少，能不能证明不可能更好。

这个转向绕开了一个几乎无望的困境。想直接证明问题 X 很难，等于去证 P≠NP，二十多年没人做到。那就改证条件命题：如果 3-SAT 很难，那么 X 也很难。

只要大家对「3-SAT 很难」有共识，整套体系就能跑起来。这个共识的名字，就是指数时间假设。

## ETH 的正式陈述

Impagliazzo 和 Paturi 在 1999 年提出，2001 年正式发表。用白话说：

> 存在常数 s > 0：3-SAT（n 个变量）在最坏情况下不能在 `O(2^(s·n))` 时间内求解。

也就是：不管你怎么巧，解 3-SAT 的时间总得是某个指数级，指数上至少正比于 n。亚指数时间，也就是 `2^o(n)`，不可能。

这里有个很漂亮的技术件，稀疏化引理（sparsification lemma，Impagliazzo–Paturi–Zane 2001）。它说任何一个 k-CNF 都能写成「至多 `2^(εn)` 个稀疏 CNF 的并」，每个稀疏 CNF 里每个变量只出现常数次。有了它，ETH 从「3-SAT 一个问题的假设」升级成「所有 k-SAT 的统一假设」：ETH 成立，等价于每个固定 k ≥ 3 的 k-SAT 都没有亚指数算法。

围绕它还有一整个家族，各管一段：

| 假设 | 断言 |
| --- | --- |
| ETH | 3-SAT 不能 `2^(s·n)`，即需要 `2^Ω(n)` |
| SETH | 对每个 ε>0，存在某个 k，使 k-SAT 不能 `2^((1-ε)n)`。k 增大时底数逼到 2，没有余量 |
| Gap-ETH | 即使 m=O(n)，也没有 `O(2^(γn))` 算法能区分「可满足」和「任何赋值都违反 δ 比例子句」的实例 |
| NSETH | 非确定性版本：没有非确定性 `2^((1-ε)n)` 算法判定 k-CNF 不可满足 |
| #ETH | 精确计数版本：精确统计 3-CNF 的满足解个数需要 `2^Ω(n)` |

这张表就是后面所有下界的地基。每一条都在说「不能更快」，所以每一条都能被一个更快的算法击穿。

## 为什么信了 27 年

三个原因。

算法进步的斜率在衰减。回到前面那张表，从 2 到 1.333 是巨幅改进，之后 1.333 到 1.308 到 1.3070，每一步都更小。SETH 的提出动机就在这个现象里：Schöning 和 PPSZ 的改进幅度随 k 增大而消失，看起来像在逼近一堵墙。

它是能干活的假设。一个假设好不好，不只看真假，还看它能不能生出一堆可检验的推论。ETH 家族在这件事上极其成功，整个细粒度复杂性子领域都是它的产物。

反例太贵。想推翻 ETH，你得交出一个真算法，不是一个论证。二十七年里没人交得出来。

## ETH 撑起的那些下界

这才是这次倒塌震感强的原因：倒的不是一个孤立猜想，是一批论文的承重墙。

参数化复杂性的最优点。以团问题 Clique 为例，`k`-Clique 最好的算法是 `n^Θ(k)`，用 ETH 做归约可以证明这个 `k` 在指数上是紧的。树宽（treewidth）参数下的独立集、支配集、约束满足，SETH 给出的界连指数底数的常数都紧。

多项式时间问题里的二次壁垒。这一类工程上最有感。SETH 曾被用来证明一批 P 内问题不可能在真正亚二次时间里解，包括编辑距离、最长公共子序列、动态时间规整、Fréchet 距离、正则表达式匹配。过去十年里那些「我们相信 O(n²) 已经最优」的说法，很多是靠 SETH 背书的。

近似算法的硬度。Gap-ETH 用来证明 Label Cover、稠密 CSP 的近似难度，也排除 Clique 和支配集在参数化近似上的非平凡算法。

动态算法的下界。维护可达性计数、动态最大强连通分量这类问题，也有挂在 SETH 链条上的下界。

一句话：细粒度复杂性里，凡是证明某算法不可能更好的论文，八成在引用 ETH 或 SETH。论文里那句轻描淡写的 assuming SETH，就是这次的震中。

## 算法做了什么

先把定理抄准确。论文 Theorem 1.1 的简化版：

> 对每个固定的 k ≥ 2，存在确定性算法，输入 n 个变量、m 个子句的 k-CNF，在 `poly(n,m) · 2^(O(n·log log n / √log n))` 位运算与多项式空间内，精确输出满足解个数 `#F`。当 m ≤ Dn（固定 D）时，界收紧到 `poly(n,m) · 2^(O(n / √log n))`。

四个修饰词都很关键。确定性，所以 ETH 的随机版本也倒了；精确计数，所以 #ETH 也倒了；多项式空间，不是拿空间换时间；每个固定宽度 k 都成立，k=3 就够击穿 ETH。

我读第 2 节技术概述时，把它的骨架分成五步。

第一步，把计数写成多项式求和。对每个子句 e 构造满足指示多项式：

```text
Φe(X) = 1 - Π_{v∈Ie} (1 - L_{e,v}(Xv))
```

在布尔点上，这个多项式在子句被满足时等于 1，否则等于 0。把全部子句乘起来，对所有 `2^n` 个赋值求和，就得到精确解个数：

```text
#F = Σ_{x∈{0,1}^n} Π_e Φe(x)
```

第二步，正视障碍。子句之间共享变量，求和拆不开。如果这堆多项式彼此不共享变量，求和立刻变成若干小组独立的求和，整个问题就变快了。现实中变量到处串门，这就是难点。

第三步，用共享线性测量切断耦合。论文引入依赖参数 T 的线性替换，把每个变量在因子里的每次出现换成带参数 T 的线性形式。T=0 时它退化成原变量；在挑过的非零 T 值上，不同变量组之间的依赖只剩下少数几个整数线性测量。把这些测量定住，每个因子就只属于一个组，求和真的分解成了独立的组内求和。

第四步，用 Hermite 插值把答案拼回来。替换后的和变成以 T 为变量的一元多项式 H(T)，我们要的 `#F` 就是 `H(0)`。只在几个点取值不够，度数会超，所以还得连泰勒系数一起算，再用 Hermite 插值（拿值和导数信息重建多项式）把 H 恢复出来，读 H(0)。

这样省的原因是：替换形式离开插值点时，偏移量每次都至少带一个因子，所以算到 q 阶泰勒系数只需要涉及至多 q 个形式坐标。再对「固定某些坐标为 1」做容斥，就能不展开整个多元多项式，直接拿到需要的系数和。

第五步，平衡三项代价。泰勒数据量、测量元组枚举、组内赋值枚举，三项相乘，最优点正好落在 `2^(n log log n / √log n)` 这个量级。附录 D 用布尔张量网络收缩重证了一遍，网络的线数直接决定代价。

对一般 k-CNF 还要先做两步无损变换：用保计数的稀疏化把实例拆成稀疏实例之和，再用 OR 门加变量复制和 Tovey 蕴含环，把每个变量的出现次数压到 3 次。整条链上解个数始终不变。

更锐的界走另一条路。在 `F_2` 上用稀疏低次多项式表示哪些子句被违反，再对若干子句集合施加稀疏奇偶校验测试。可行赋值能通过所有测试，但任意校验系统都可能漏过不合格赋值，于是论文用 expander 码（Tanner 码）让漏网的赋值在扩展图上违反大量子句，再用确定性贪心挑测试、用模整数多项式把「偶数个违反」变成精确表达式里的一个因子，保证计数不失真。

论文自己写了限制：**`2^o(n)` 的加速不会通过一般多项式时间归约传递**，那需要 `2^(n^o(1))`。所以这个结果不蕴含一般 NP 问题有亚指数算法。要把加速搬到具体问题上，需要一个能控制变量数的归约。论文点名的正面例子是 Set Splitting，一个元素一个布尔变量，固定 k 时直接给出宇宙规模上的亚指数算法。

## 交叉点在哪

这一节我自己算了一遍，因为媒体上流传的版本五花八门，我对不上。

比较对象是当前最好的 3-SAT 算法：随机 1.307031578^n（Jiang–Cai preprint），确定性 1.32793^n（Liu 2018）。新界的指数是 `n / √(ln n)`，对数取自然对数，忽略多项式因子，常数都按 1 算：

```python
import math

def new_exp(n):      # 2 的指数部分
    return n / math.sqrt(math.log(n))

def old_exp(n, base):
    return n * math.log2(base)

for n in [10**3, 10**4, 10**6]:
    print(n, new_exp(n), old_exp(n, 1.307031578))
# 1000     380.5     386.3
# 10000    3295.1    3862.9
# 1000000  269040    386294
```

交叉点，也就是新算法第一次跑赢现有最好算法的变量数：

```text
新界 vs 随机 1.307032^n                 n ≈ 814
新界 vs 确定性 1.32793^n                n ≈ 393
完整界（含 log log n 因子）vs 1.307032^n   n ≈ 4.8 × 10^78
```

三个读数。用最简化的界、忽略所有多项式因子，大约 814 个变量之后新算法才有理论优势，而在那个尺寸上双方都跑不动，比的只是指数增长率。用论文完整界，交叉点跑到 10 的 78 次方量级，比可观测宇宙的原子数大得多。Lean 里形式化那版的界更松，媒体算出来的交叉点是 n 有大约 2400 位十进制数。

所以这不是一个能用的算法，是一个能改教科书的算法。工程上马上要改的，只是那些写着 assuming ETH 的论文脚注。

## 什么倒了，什么还站着

倒掉的是 ETH、SETH、Gap-ETH、NSETH、#ETH，以及它们的随机化版本，还有建立在这些假设上的全部条件下界。注意用语：那些定理在逻辑上没变成假，而是变成空真，前提不成立，蕴涵式自动为真。数学上还算成立，信息量为零。

还站着的，有几件：

| 还活着 | 说明 |
| --- | --- |
| P ≠ NP | 完全没被触及。`2^o(n)` 不传递 |
| OVC（正交向量猜想） | LCS、正则表达式匹配的下界可以从 OVC 重新推导，不必挂 SETH |
| 一般 CNF-SAT 假设 | 「宽度随 n 增长的一般 CNF-SAT 没有 `2^((1-δ)n)` 算法」没被推翻。新算法只对固定宽度 k 成立 |
| 证明系统的指数下界 | 例如 regular resolution 的无条件下界，跟 ETH 无关 |
| 密码学 | 攻击密码学需要多项式时间算法，这里没有。Williams 让人检查过，暂时没有现成密码系统被波及 |
| 弱 ETH | `2^(n^(1-ε))` 这种弱化版本仍可能成立，很多人会改用这个 |
| 部分参数化下界 | 挂在 k-Orthogonal Vectors 那类的还能留 |

另有一批无条件结论掉出来了，这是我觉得整件事里最有意思的部分。

Ryan Williams 2013 年有个条件结果：如果 ETH 是假的，那么 ENP 不包含在 SIZE(O(n)) 里，也就是存在一个 NP 可解、但没有线性大小电路的语言。前半句现在成了定理，所以后半句无条件成立。论文给出 `ENP ⊄ SIZE(O(n))`，定量版本是存在语言 `L ∈ ENP` 与常数 c>0，使无穷多个 n 上电路门数 `C_L(n) > c·√(n log n)`。

顺带掉出来的具体算法还有几个。图上精确计数：独立集个数、固定 q 的 q-着色方案数 `2^o(v)` 时间，完美匹配数 `2^o(v+e)`。Max-k-SAT 近似：对任意 ε>0，以 `1-2^(-Ω(n))` 的概率找到满足至少 `OPT-εm` 个子句的赋值。常数局部布尔映射的反演：`2^o(n)` 内可精确计数、求原像、均匀采样，这直接排除了 Goldreich 那类候选单向函数的 `2^Ω(n)` 反演硬度，但不排除多项式时间单向性，所以密码学仍安好。

## 后 ETH 时代怎么活

理论计算机科学界的实际反应比「震惊」复杂得多。cstheory 上 10 月 27 日最热的问题就叫《How to salvage arguments that assume ETH》，作者的观察很到位：如果这些声称成立，一大批不可能性结果变成空真，但论文的概念信息大多还在，对目标问题拿到更快的算法，就等于 3-SAT 的改进算法。

Michael Lampis 的回答给了条实用路线，把 ETH 换成更弱但仍够用的假设，比如「3-SAT 不能在 `2^(n^(1-ε))` 时间内求解」。然后按依赖程度分类自己的结果。

FPT 最优性里那些大函数的结果还能活。比如证明某问题不能 `2^o(k²)`，归约从 N 变量 3-SAT 出发令 `k = Θ(√N)`，换成弱 ETH 只是把界弱化成 `2^(k^(1-ε))` 之类，仍然有话可说。

基本报废的是这档程序里最有意思的部分，也就是区分「略超指数 `k^Θ(k)`」和「指数」的精细结果。弱 ETH 不够细，挡不住指数上的对数级改进。

存疑的是基于 k-Clique 的 XP 最优性结果，暂时看不到怎么在弱 ETH 下重建。Lampis 提到 k-支配集这类可以挂到 k-Orthogonal Vectors 假设上的结果「暂时看着还行」，因为 k-OV 假设本身还活着。

要重做的是树宽参数下连常数都紧的最优性，那本来是 SETH 的地盘，得换一套假设体系。

## 我需要修正的三个判断

写完上面这些，说说我自己此前想错的地方。

第一个，我以为 ETH 这种「大家都相信但没人证明」的假设会活得更久。它的支持度有两个来源：算法改进的斜率在衰减，以及它生出了一整个子领域。这两条在 27 年里被反复验证，看起来像经验规律。结果真正的原因可能只是没人想到那个多项式替换的技巧。经验规律的保质期比想象中短。

第二个，我以为条件性下界是安全的研究方式，因为它不赌真假，只赌依赖关系。这次事故说明它赌的是另一件事：赌那个前提假设不会在某天被一个具体构造推翻。「条件」二字给了心理上的安全感，实际上只是把风险挪到了别处。

第三个，我原以为这类结果会先出现在社区 preprint 里，由某个博士生贴出来。这次是 AI 先给出自然语言证明，一天后 Lean 通过，然后连同形式化文件一起公开，验证工作交给原假设的提出者。这个流程本身比 ETH 倒掉更值得记。

对不做复杂性理论的人，我认为实际影响只有一条：以后看到 assuming ETH，多问一句这条结论有没有别的假设撑着。有就换，没有就把结论降级成历史共识。我自己那几篇讲检测和压缩的文章里也有不少这类引用，回头得挨个查。

论文和 Lean 文件在 [github.com/openai/math](https://github.com/openai/math/tree/main/preprints/The-Exponential-Time-Hypothesis-is-False-October-25-2026)，第 2 节的技术概述写得比大部分论文都清楚，自己读一遍比看任何二手解读都强。
