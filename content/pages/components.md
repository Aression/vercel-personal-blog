写长文时反复要用的那几块排版，都做成了组件。下面每一节都是「实际效果 + 源码」，抄过去就能用。

组件由 `build.py` 的 `:::` 容器语法生成，样式在 `assets/site.css`，交互在 `assets/site.js`。全部是纯 CSS/JS，没有框架、没有外部请求。

## 提示框

四种语义色，加 `:::note` `:::tip` `:::warn` `:::insight` 都行，后面跟的标题会覆盖默认文案。

:::note 设计取舍
默认标题可以省略。这个框适合放「为什么这么做」这类背景说明。
:::

:::tip
跑构建前先 `pip install markdown`，公式还需要 `node` + `npm i katex`，缺了只会降级不会中断。
:::

:::warn 别把结论当事实
压缩摘要把假设写成陈述句，是这个项目最初的事故来源。反证据要当一等公民对待。
:::

:::insight
组件的边界就是 Markdown 的边界：脚注、目录、公式在容器里都照常工作，因为它们最后是同一趟渲染。
:::

## 折叠

长推导、大段日志、可跳过的实现细节，收进 `:::details 标题` 里。

:::details 展开看一个真实的失败模式
第 40 轮把已经用 4 个探针排除过的路径又跑了一遍，因为第 12 轮那条发现被摘要成了一句「排查了 tokenizer 相关问题」。

摘要没骗人，但丢掉了「在哪个 commit、什么 dtype 下成立」这个前提。
:::

## 标签页

同一件事的多个视角、多种语言的同一段代码，用 `:::tabs` 套 `:::tab 名称`。键盘左右方向键可以切换。

:::tabs
:::tab 认知状态
一条发现是 `supported` 就是有证据支持，`refuted` 是被证伪。这一维只回答「现在信不信」。
:::
:::tab 生命周期
`active` / `superseded` / `archived`，回答「还要不要继续用」。被新结论替代不代表原结论当时是错的。
:::
:::tab 适用性
`applicable` / `stale` / `unknown`，回答「在当前 commit、后端、dtype 下还成不成立」。条件不明一律落到 `unknown`。
:::
:::

三个状态互不替代，`refuted` 不等于 `superseded`——这是整个设计里最不肯让步的一条。

## 步骤

有先后顺序的流程用 `:::steps` 套 `:::step 标题`，自动编号并连线。

:::steps
:::step 收集
把每次实验的探针、结果、适用范围写进账本，结论和依据分开存。
:::
:::step 判定
新证据进来只更新对应的发现，不重写整段摘要，避免历史被覆盖成一句糊话。
:::
:::step 注入
按当前 commit 与后端过滤，只把仍然 applicable 的发现塞回上下文，带 token 预算。
:::
:::

## 代码块

围栏后面可以跟语言名，再跟一个 `title=` 当文件名。构建时就完成语法高亮，页面不加载任何高亮库。

```python title=ledger.py
def applicable(finding, ctx):
    """条件不明一律落到 unknown，不要静默匹配成功。"""
    if not finding.scope:
        return "unknown"
    if finding.scope.commit != ctx.commit:
        return "stale"
    return "applicable"
```

```bash title=构建与本地预览
cd ~/lvdi-profile
python3 build.py
python3 -m http.server 8899
```

## 数学公式

行间公式用 `$$...$$` 或 `\[...\]`，行内用 `\(...\)` 或 `$...$`。构建时用 KaTeX 渲染成静态 HTML，零 JS 依赖，打印和 RSS 都正常。

指数时间假设断言的是最坏情况下的下界：

$$
\exists\, \varepsilon > 0,\ \forall\ \text{algorithms}\ A:\ T_A(n) = \Omega\!\left(2^{\varepsilon n}\right)
$$

行内的样子：$T(n) = 2T(n/2) + O(n)$ 解出来是 $O(n\log n)$。

## 脚注

正文里 `[^1]` 标号，文末写定义，编号自动连续，即使跨组件也统一[^1]。

[^1]: 这条脚注故意写在容器外面，验证编号不会因为组件嵌套而错乱。

## 组件嵌套

组件可以互相嵌套，代码块和公式在容器内部也照常工作。

:::details 一个嵌套例子
:::tip
提示框里放代码：

```javascript
const findings = ledger.filter(f => f.applicable(ctx));
```
:::

外面再套一层折叠，依然正常展开与高亮。
:::

## 写在最后

新增组件只需要两步：在 `build.py` 的 `render_container` 里加一个分支，在 `assets/site.css` 里加样式。要交互就再往 `assets/site.js` 里加一段——像 `tabs` 那样从 `data-` 属性挂上去，不依赖具体页面。
